# BoardMate — фронтенд

Каталог настільних ігор, реєстрація, JWT-вхід і закрита сторінка власного акаунта. Написано на HTML, CSS та JavaScript без фреймворку.

## Як запустити проєкт

Потрібен Python 3. Спочатку запустіть [бекенд BoardMate](https://github.com/SigmaSigmaSigmaSigmaSigmaSigmaSigmaSigm/boardmate) з гілки `feat/jwt-accounts`: встановіть залежності, застосуйте міграції та виконайте `python manage.py runserver 8000` за його README.

У папці фронтенду:

```sh
python3 -m http.server 5500 --bind 127.0.0.1
```

Відкрийте [каталог](http://127.0.0.1:5500/). Збірка або npm для запуску не потрібні.

- Фронтенд: `http://127.0.0.1:5500/`.
- Бекенд: `http://127.0.0.1:8000/`.
- API: `http://127.0.0.1:8000/api/`.

Бекенд дозволяє CORS для `http://127.0.0.1:5500` та `http://localhost:5500`. Відкривайте сторінки через HTTP-сервер, а не як локальні файли.

## Сторінки

| Сторінка        | Доступ і поведінка                                                                                        |
| --------------- | --------------------------------------------------------------------------------------------------------- |
| `index.html`    | Відкритий каталог ігор з пагінацією. Гість бачить посилання входу та реєстрації.                          |
| `register.html` | Реєстрація з підтвердженням пароля й повідомленнями помилок біля полів. Після успіху відкривається логін. |
| `login.html`    | Вхід за ніком і паролем. Якщо користувач уже увійшов, відкривається сторінка контенту.                    |
| `account.html`  | Тільки для авторизованих: власні ім’я, прізвище, нік, пошта та роль, отримані через `/api/me/`.           |

Гість, який відкриває `account.html`, потрапляє на `login.html?next=/account.html`. Після входу повертається на цю сторінку. Зовнішні адреси в `next` не дозволені.

Після входу навігація показує ім’я (або нік, якщо ім’я порожнє) і кнопку «Вийти» замість посилання логіну. Захист сторінки перевіряє JWT через API: самої наявності рядка токена у сховищі недостатньо. Права на зміну каталогу перевіряє бекенд: тільки `is_staff=True`. Форм керування каталогом у цій роботі немає.

## JWT, refresh і logout

`POST /api/auth/login/` повертає `access` і `refresh`, які зберігаються у `sessionStorage` поточної вкладки. Захищені запити мають заголовок `Authorization: Bearer <access>`.

Access діє 5 хвилин, refresh — добу. Коли захищений запит повертає `401`, `auth.js` надсилає refresh до `/api/auth/refresh/`, зберігає новий access і повторює запит один раз. Одночасні запити використовують одне оновлення. Якщо refresh недійсний або прострочений, токени видаляються і закрита сторінка перенаправляє на логін. Тимчасова мережева помилка не видаляє токени: сторінку можна перезавантажити після відновлення з’єднання.

Кнопка «Вийти» видаляє обидва токени та відкриває каталог. Закриття вкладки також очищає її `sessionStorage`. Сервер не відкликає вже видані токени. Це навчальне зберігання токенів, доступне JavaScript поточної сторінки; дані API виводяться через `textContent`, а не HTML.

## Перевірки

Потрібен Node.js 22 або новіший:

```sh
npm ci
npm run check
```

Запускаються Prettier, HTML Validate, Stylelint, перевірка синтаксису JavaScript і тести через вбудований `node:test`. Тести покривають повтор запиту після refresh, одночасні запити, недійсний refresh, мережеву помилку, logout під час refresh і безпечну адресу повернення.

Окремо `npm test` запускає тільки тести. Результати перевірки сторінок у браузері вказані в PR.
